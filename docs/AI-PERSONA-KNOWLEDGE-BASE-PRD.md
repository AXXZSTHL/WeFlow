# AI 分身知识库产品文档

## 1. 背景

当前 AI 分身已经具备基础的人格画像、对话模拟和增量更新能力，但它仍然更像“一个结构化技能卡片”，而不是“一个可以持续积累、可查看、可维护、可追溯的分身知识库”。

当用户把多个私聊、群聊、历史回复一起纳入分身时，原始聊天量会快速膨胀。如果只依赖一次性总结，分身会越来越失真；如果只依赖原文直塞，上下文会越来越长，无法稳定回答，也无法维护。

本方案的目标是把 AI 分身升级为一个真正的产品级能力：

- 每个分身拥有独立知识库
- 原始聊天、摘要记忆、回答证据分层存储
- 支持自动增量更新
- 支持用户查看、筛选、排除、置顶、纠错
- 支持回答时引用知识库来源，形成可追溯链路

## 2. 产品目标

### 2.1 用户目标

- 用户可以把多个私聊或群聊纳入“我的 AI 分身”
- 用户可以查看分身到底学到了什么
- 用户可以纠正系统提炼错误的内容
- 用户可以知道每次回答依据了哪些历史内容
- 用户不需要手工维护原始聊天记录

### 2.2 系统目标

- 长聊天自动切片、摘要、归档
- 以 RAG 思路组织回答上下文
- 支持增量更新，不全量重算
- 支持知识库检索与回答证据链
- 支持后续扩展到向量检索，不锁死实现路径

## 3. 核心原则

1. 原始数据不能丢。
2. 摘要必须可回到原文。
3. 回答必须能追溯到证据。
4. 用户维护只作用于高价值内容，不要求维护全部聊天。
5. 分身知识库是持续演进的，不是一次性生成的。
6. 对话风格和知识事实分层存储，不能混成一个 prompt。

## 4. 能力边界

### 4.1 本期范围

- AI 分身知识库分层存储
- 自动切片与摘要
- 知识库列表与维护
- 回答证据记录
- 聊天时自动检索相关知识
- 分身增量更新时自动补充知识库

### 4.2 非目标

- 不做人工知识编辑器替代聊天软件
- 不做全量语义搜索平台
- 不做跨账号共享知识库
- 不做复杂训练或微调系统
- 不把模型输出当作唯一事实来源

## 5. 知识库分层设计

### 5.1 原始层

原始层保存每段对话切片的原文信息，作为所有摘要和检索的底座。

字段建议：

- 片段 ID
- 分身 ID
- 来源会话 ID
- 说话人范围
- 起止时间
- 原文
- 消息数量
- 状态：active / pinned / excluded
- 标签
- 重要度

### 5.2 摘要层

摘要层从原始片段中提炼出可复用的长期信息。

摘要内容建议分为：

- 事实记忆
- 偏好记忆
- 关系记忆
- 语气记忆
- 行为规则
- 示例回复
- 边界情况

### 5.3 证据层

证据层保存每次 AI 回答命中的历史片段和记忆项，用于：

- 查看回答依据
- 纠错
- 回溯
- 后续相似问题复用

## 6. 检索与回答策略

### 6.1 推荐策略

本期采用 **RAG 思路 + 关键词/分词召回 + 元数据过滤 + 重排** 的混合方案。

原因：

- 现有工程已经具备 OpenAI 兼容对话调用能力
- 产品目标首先是稳定、可解释、可维护
- 不引入额外复杂依赖也能先跑通产品闭环
- 后续可以无缝替换或叠加向量检索

### 6.2 检索流程

1. 输入用户问题或待回复内容
2. 优先检索当前分身的知识库
3. 使用标题、摘要、原文、标签做关键词召回
4. 结合时间、会话、状态、重要度重排
5. 把命中证据注入模型上下文
6. 生成回答
7. 记录本次回答引用了哪些知识片段

### 6.3 召回优先级

- 用户置顶内容优先
- 最近更新内容优先
- 高置信摘要优先
- 与当前问题语义最相关的片段优先
- 已排除内容不参与召回

## 7. 用户维护设计

用户不维护原始聊天本身，只维护系统提炼出来的高价值部分。

支持操作：

- 查看原文
- 查看摘要
- 修改摘要
- 标记重要
- 置顶
- 排除
- 恢复
- 搜索
- 查看来源会话
- 查看回答命中记录

## 8. 页面设计

### 8.1 分身详情页

新增 `知识库` Tab，展示：

- 原始片段列表
- 摘要记忆列表
- 回答证据列表
- 搜索与筛选
- 维护操作入口

### 8.2 主要信息展示

每条知识项建议展示：

- 标题
- 摘要
- 原文预览
- 来源会话
- 时间范围
- 标签
- 状态
- 命中次数

### 8.3 操作入口

- 复制摘要
- 复制原文
- 置顶/取消置顶
- 排除/恢复
- 查看回答引用

## 9. 数据模型建议

### 9.1 知识项

```ts
interface PersonaKnowledgeItem {
  id: string
  personaId: string
  type: 'source_chunk' | 'session_summary' | 'memory_item'
  title: string
  summary: string
  rawText: string
  sourceSessionIds: string[]
  sourceMessageCount: number
  sourceDateRange: { startTime: number; endTime: number }
  tags: string[]
  status: 'active' | 'pinned' | 'excluded'
  importance: number
  confidence: number
  createdAt: number
  updatedAt: number
}
```

### 9.2 回答证据

```ts
interface PersonaAnswerTrace {
  id: string
  personaId: string
  question: string
  answer: string
  retrievals: Array<{
    itemId: string
    title: string
    score: number
    reason: string
  }>
  createdAt: number
}
```

## 10. 增量更新规则

- 新消息先入原始层
- 新切片才做摘要
- 已处理过的旧片段不重复重算
- 新增内容只增量补充知识库
- 用户修改优先级高于自动提炼
- 删除/排除立即生效

## 11. 风控与隐私

- 原始内容默认只在本地保存
- 群聊内容必须支持显式勾选来源
- 用户可排除敏感对话
- 分身之间知识库隔离
- 回答证据仅供当前用户可见
- 删除分身时同步删除其知识库和证据链

## 12. 里程碑

### M1

- 知识库存储
- 详情页查看
- 增量入库
- 知识项维护

### M2

- 检索增强回答
- 回答证据链
- 相似问题命中来源展示

### M3

- 向量检索扩展
- 自动聚类与主题分组
- 更强的历史回复复用

## 13. 验收标准

- 分身生成后可看到知识库条目
- 新消息更新后知识库会增量增加
- 用户可排除或置顶某条知识
- 聊天回答可记录引用来源
- 关闭或重启后知识库仍可恢复
- 不要求用户手工维护聊天原文
